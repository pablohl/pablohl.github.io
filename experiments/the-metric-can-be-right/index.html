What happens after an alert?

Now imagine a larger workload.

Keep the same illustrative alert rates. What if the workflow processed 100,000 transactions?

This is a projection, not a measured operational result. Evidence access belongs to the surrounding product workflow, not necessarily the predictive model itself. The two configurations would need to be assessed as complete systems.

What changed? The evaluation boundary grew from model output to human review. A single case suggests a possible difference; it does not establish an average workload.

Beyond this model

What did the metric throw away?

The right question is not “What else could we measure?” There is always more. Ask whether omitted information could plausibly change this decision. If it cannot, move on. If it can, investigate that boundary.

How this illustrative model works

The test contains 10,000 transactions, including 200 fraudulent ones. Model A misses 60 fraud cases and falsely declines 20 legitimate ones; Model B misses 20 and falsely declines 80. Thus A has 9,920 correct predictions (99.2%) and B has 9,900 (99.0%). The marks show a representative one-tenth slice of that evaluation, not a separate measurement.

The cost comparison assumes $600 per missed fraud case, a reader-adjustable amount per false decline, and the stated model running costs. The review projection uses 160 A alerts or 260 B alerts per 10,000 transactions, the illustrative case times of 10 and 2 minutes, and $40 per analyst-hour. It does not establish actual review times, true loss distributions, customer effects, or a deployment recommendation. All figures and interfaces are invented to expose the decision boundary.
